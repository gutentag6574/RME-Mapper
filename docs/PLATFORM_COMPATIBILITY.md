# Платформенная совместимость GeoPoint Mapper

В данном документе описывается целевая архитектура многоплатформенной поддержки приложения **GeoPoint Mapper** для современных и устаревших операционных систем семейства Microsoft Windows.

---

> [!IMPORTANT]
> **Текущий статус**: На текущем этапе кодовая база проекта функционирует исключительно в рамках **Modern Build (Windows 10 / 11 x64)**. Поддержка Windows 7 и Windows XP является **целевой задачей будущих отдельных этапов разработки**. Текущая сборка на базе PySide6 и современного Python **НЕ работает** на Windows 7 и Windows XP.

---

## 1. Обзор целевых сборок приложения

В будущем GeoPoint Mapper будет выпускаться в трех независимых вариантах сборки:

| Параметр | GeoPoint Mapper Modern | GeoPoint Mapper Legacy 7 | GeoPoint Mapper Legacy XP |
| :--- | :--- | :--- | :--- |
| **Целевая ОС** | Windows 10 x64, Windows 11 x64 | Windows 7 SP1 (x86 / x64), Windows 8.1 | Windows XP SP3 (x86) |
| **Архитектура** | x86-64 (AMD64) | x86 (32-bit) / x64 | x86 (32-bit) |
| **Версия Python** | Python 3.12+ (актуальные релизы) | Python 3.8.x (последний официальный для Win7) | Python 3.4.4 (последний официальный для Win XP) |
| **GUI Framework** | PySide6 (Qt 6.6+) | PyQt5 (Qt 5.15) или PySide2 (Qt 5.12) | PyQt4 (Qt 4.8) или PySide 1.2 |
| **GIS стек** | GeoPandas 1.0+, Shapely 2.0+, pyproj 3.6+, pyogrio | GeoPandas 0.9/0.10, Shapely 1.8, pyproj 2.6/3.x | Custom SQLite3 GeoPackage reader / pure Python GIS |
| **Потребление RAM** | Не ограничено (64-битное адресное пространство) | Ограничено для x86 (до 2 ГБ) | Жесткий лимит: до 2 ГБ на процесс (до 3 ГБ с /3GB) |
| **Формат проекта** | `*.gpmap` (UTF-8 JSON, v1) | `*.gpmap` (UTF-8 JSON, v1) | `*.gpmap` (UTF-8 JSON, v1) |

---

## 2. GeoPoint Mapper Modern (Текущая сборка)

- **Платформа**: Windows 10 x64, Windows 11 x64.
- **Инструменты**:
  - Python 3.12+
  - PySide6 для высокопроизводительного аппаратного рендеринга `QGraphicsScene` / `QGraphicsView`.
  - Полнофункциональный GIS стек: `geopandas`, `shapely`, `pyproj` (PROJ 9+), `pyogrio` (GDAL).
- **Назначение**: Основная версия с максимальной точностью геодезических вычислений на эллипсоиде WGS84, поддержкой сложных векторных стилей и высокой скоростью рендеринга сотен тысяч объектов.

---

## 3. GeoPoint Mapper Legacy 7 (Планируемая сборка)

- **Платформа**: Windows 7 SP1 (x86 и x64), Windows 8.1.
- **Особенности и ограничения**:
  - Официальный дистрибутив CPython прекратил поддержку Windows 7 после версии Python 3.8.10.
  - Qt 6 не поддерживает Windows 7 из-за отсутствия системных вызовов ядра Windows (требуются API Windows 10+).
  - Сборка будет основываться на **PyQt5** или **PySide2** (Qt 5.15 LTS).
  - Версии `geopandas` и `shapely` ограничены версиями, собранными под Python 3.8 (Shapely 1.8.x, pyproj 2.6/3.2).
- **Архитектурное сопряжение**:
  - Единая бизнес-логика (модели данных `MapPoint`, `ProjectData`, валидация координат `CoordinateValidator`).
  - Абстрагированный GUI-слой (общие сигналы и слоты, аналогичная компоновка панелей).

---

## 4. GeoPoint Mapper Legacy XP (Планируемая сборка)

- **Платформа**: Windows XP SP3 (x86, 32-bit).
- **Особенности и ограничения**:
  - Python 3.4.4 — последний официальный релиз CPython, работающий на Windows XP.
  - Microsoft Visual C++ 2010 (MSVC 10.0) — базовый компилятор для C-расширений.
  - Современные библиотеки GIS (`geopandas`, `pyogrio`, `shapely 2.x`, `pyproj 3.x`) физически не могут быть скомпилированы и запущены на Windows XP.
  - Сборка потребует специализированного бэкенда: **`LegacyGeoPackageBackend`**.
  - Чтение векторных данных GeoPackage будет выполняться напрямую через стандартный модуль `sqlite3` (чтение таблиц `gpkg_contents`, `gpkg_geometry_columns` и бинарных BLOB геометрии WKB/GPKG).
  - Геодезические расчеты зон будут выполняться по аналитическим формулам Винсенти / Карни на чистом Python без зависимости от внешних бинарных библиотек PROJ/GDAL.
  - GUI будет основан на PyQt4 (Qt 4.8) или PySide 1.2.

---

## 5. Ограничения 32-битной архитектуры (RAM Limits)

В 32-битных версиях Windows (особенно Windows XP x86):
- Каждому пользовательскому процессу доступно максимум **2 ГБ виртуального адресного пространства** (в редких конфигурациях с ключом `/3GB` в `boot.ini` — до 3 ГБ).
- В это адресное пространство загружаются: интерпретатор Python, библиотеки DLL (Qt, C runtime), буферы растрирования GUI, кэш геометрий.
- При загрузке тяжелых векторных слоев (полигоны с десятками тысяч вершин) неконтролируемое потребление памяти приводит к фатальному исключению `MemoryError`.

### Требования к будущей оптимизации под 32-bit:
1. **Lazy loading**: загрузка геометрий слоев в память только при включении их видимости.
2. **Упрощение геометрии (Simplification)**: генерализация полигонов при отображении обзорных масштабов.
3. **Выборочная загрузка слоев**: загрузка только атрибутов и геометрий, необходимых для текущего сеанса.
4. **Ограничение количества объектов (Feature limits)**: потоковая обработка или лимитирование отображаемых полигонов.
5. **Клиппинг по Viewport**: отрисовка только тех элементов слоя, которые попадают в границы текущего экрана.

## 6. Единый межплатформенный формат проектов (*.gpmap)

Все версии приложения (Modern, Legacy 7, Legacy XP) используют единый формат файла проекта — `*.gpmap`:
- Текстовый формат на базе **UTF-8 JSON**.
- Полное отсутствие специфичных для конкретной ОС путей (хранение относительных путей `relative_path`).
- Полное отсутствие Qt-специфичных типов данных (`QColor`, `QPainterPath`, `QGraphicsItem`).
- Проект, сохраненный в Modern-версии, сможет быть открыт в Legacy-версиях, и наоборот.
