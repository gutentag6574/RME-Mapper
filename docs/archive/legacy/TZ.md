# Техническое задание — RME Mapper

## 1. Назначение

Разработать настольное приложение для Windows для нанесения географических координат на заранее подготовленные карты Республики Марий Эл.

Программа должна позволять:

- выбрать карту;
- ввести одну или несколько координат вручную;
- импортировать координаты из XLSX, CSV и TXT;
- проверить корректность координат;
- преобразовать координаты в CRS выбранной карты;
- отобразить точки на карте;
- выбрать форму, размер и RGB-цвет точки;
- построить вокруг точки зону заданного радиуса;
- экспортировать итоговую карту в PNG/JPEG;
- сохранить и повторно открыть проект.

## 2. Основной принцип

Главным объектом является реальная географическая координата, а не координата пикселя.

Схема обработки:

`ввод пользователя -> валидация -> нормализация -> преобразование CRS -> координаты карты -> экран`

## 3. Карты

Программа должна поддерживать заранее подготовленный каталог карт.

Для каждой карты хранятся:

- ID;
- название;
- описание;
- файл карты;
- CRS;
- географический охват;
- источник;
- год;
- масштаб, если известен;
- параметры геопривязки.

Добавление новой карты не должно требовать изменения основного кода программы.

## 4. Системы координат

CRS нельзя жестко зашивать в код.

Для карты должна поддерживаться возможность описания через:

- EPSG;
- WKT;
- PROJ;
- пользовательскую CRS.

Преобразование координат должно выполняться специализированной GIS-библиотекой.

Предполагаемый вариант: `pyproj` / PROJ.

## 5. Ввод координат

Обязательные форматы:

### DD

Десятичные градусы.

Пример:

`56.637556, 47.886306`

### DMS

Градусы, минуты, секунды.

Пример:

`56°38'15.2\" N, 47°53'10.7\" E`

Должны быть отдельные поля для градусов, минут и секунд.

Нулевые минуты и нулевые секунды допустимы.

## 6. Валидация координат

Широта:

- градусы: 0–90;
- минуты: 0–59;
- секунды: >= 0 и < 60.

Долгота:

- градусы: 0–180;
- минуты: 0–59;
- секунды: >= 0 и < 60.

Поддерживать `N/S` и `E/W`.

Дробная часть должна приниматься как через точку, так и через запятую, если это возможно без неоднозначности.

## 7. Работа с точками

Для каждой точки хранить:

- ID;
- название;
- исходную широту;
- исходную долготу;
- формат исходных координат;
- исходный CRS;
- нормализованную широту;
- нормализованную долготу;
- X/Y после преобразования;
- целевой CRS;
- форму;
- размер;
- RGB;
- радиус;
- единицу радиуса;
- подпись;
- комментарий;
- видимость.

## 8. Оформление точек

Обязательные формы:

- круг;
- квадрат;
- треугольник.

Цвет:

- визуальный выбор;
- RGB 0–255;
- желательно HEX.

## 9. Радиусы

Радиус задается в:

- метрах;
- километрах.

Радиус должен соответствовать реальному расстоянию на местности, а не фиксированному числу пикселей.

Настройки зоны:

- радиус;
- цвет контура;
- цвет заливки;
- прозрачность;
- толщина контура.

## 10. Пакетный импорт

Обязательные форматы:

- XLSX;
- CSV;
- TXT.

Для первой версии обязательны как минимум два шаблона:

1. `name, latitude, longitude`
2. DMS по отдельным столбцам.

Каждая строка проверяется отдельно.

При ошибке показывать:

- номер строки;
- поле;
- значение;
- причину ошибки.

Пользователь должен иметь возможность импортировать только корректные строки.

## 11. Таблица точек

В интерфейсе должна отображаться таблица всех точек.

Функции:

- выбрать;
- центрировать карту;
- редактировать;
- удалить;
- показать/скрыть;
- массово изменить оформление выбранных точек.

## 12. Экспорт

Обязательные форматы:

- PNG;
- JPEG/JPG.

На экспортируемом изображении должны отображаться:

- карта;
- точки;
- радиусы;
- подписи, если включены.

## 13. Сохранение проекта

Сохранять:

- выбранную карту;
- точки;
- исходные координаты;
- преобразованные координаты;
- оформление;
- радиусы;
- подписи;
- настройки отображения.

## 14. MVP

Первая полноценная версия должна включать:

1. загрузку карты;
2. масштабирование и перемещение;
3. преобразование CRS;
4. ручной ввод DD/DMS;
5. проверку координат;
6. таблицу точек;
7. круг/квадрат/треугольник;
8. RGB;
9. радиус;
10. XLSX/CSV/TXT;
11. экспорт PNG/JPEG;
12. сохранение проекта.

## 15. Контроль точности

До приемки необходимо сравнить положение контрольных точек с QGIS.

Минимум 5 контрольных точек:

- север;
- юг;
- запад;
- восток;
- центр.

Желательно 10–20 точек.

## 16. Исходные материалы

Для разработки необходимы:

- минимум одна тестовая карта;
- CRS слоя карты;
- CRS проекта QGIS;
- WKT/PROJ или EPSG;
- контрольные координаты;
- эталонные X/Y из QGIS, если возможно;
- пример XLSX;
- материалы по системе Животовского/Османовой;
- сведения о координатных зонах.

## 17. Важное ограничение

До подтверждения корректного преобразования координат нельзя считать картографическое ядро готовым.

Первый технический прототип должен доказать:

`одна известная координата -> правильное место на карте -> совпадение с QGIS`.
