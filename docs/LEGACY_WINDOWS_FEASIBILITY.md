# Исследование технической осуществимости и матрица совместимости (Legacy Windows Feasibility)

**Продукт**: GeoPoint Mapper  
**Версия**: 0.12.0  
**Этап**: Этап 24 — Совместимость с устаревшими версиями Windows (Windows 7 / Windows XP Feasibility)  
**Дата аудита**: 22 сентября 2026 г.  

---

## 1. Введение и цели аудита

Главная цель данного исследования — всесторонний технический аудит возможности запуска и функционирования настольного ГИС-приложения **GeoPoint Mapper** на устаревших операционных системах семейства Microsoft Windows:
1. **Windows 7 SP1** (x86 и x64, релиз 2009 г., окончание расширенной поддержки Microsoft: январь 2020 г.);
2. **Windows XP SP3** (x86, релиз 2001 г., окончание поддержки Microsoft: апрель 2014 г.).

### Базовые ограничения и принципы исследования:
- **Единая кодовая база (One Source Tree)**: категорически запрещено создавать изолированные форки вида `src/rme_mapper_legacy/` или отдельные копии контроллеров/моделей. Архитектура ядра и форматы данных должны оставаться едиными.
- **Сохранение Modern Build**: современный стек Windows 10/11 x64 (Python 3.12+, PySide6 6.6+, GDAL/rasterio 1.3+, Shapely 2.0+, pyproj 3.6+, numpy 1.26+) остается основным и не подвергается глобальному понижению версий ради старых платформ.
- **Нулевая толерантность к небезопасному TLS**: запрещено использование `verify=False`, отключение валидации SSL-сертификатов, подавление TLS-ошибок, HTTP fallback для HTTPS-провайдеров или принудительное понижение до устаревших шифров SSLv3/TLS 1.0. Если платформа не может обеспечить криптографически безопасный обмен по современным стандартам TLS 1.2/1.3, сетевые функции (Online Maps) должны быть **отключены**.
- **Честная фиксация статусов**: недопустимо выставлять статус `VERIFIED` или `PASS` без непосредственного запуска на реальной целевой ОС или валидированной виртуальной машине.

## 3. Детальный аудит Windows 7 SP1

### 3.1. Минимальный надежный стек Windows 7
- **Интерпретатор**: CPython **3.8.10** (официальный Windows x86/x64 installer).
- **GUI Framework**: **PyQt5 5.15.10** (или **PySide2 5.15.2.1**).
- **GIS Core**: `numpy==1.24.4`, `shapely==2.0.1`, `pyproj==3.5.0` (с бандлированным `proj.db`), `openpyxl==3.1.2`, `Pillow==10.0.0`.
- **Растровый стек**: `rasterio==1.3.6` (возможен для x64) либо встроенный `LegacyRasterBackend` для легких растров.
- **Векторный стек**: `pyogrio==0.6.0` либо стандартный `sqlite3` GeoPackage reader.
- **Системные требования Windows 7**:
  - Windows 7 Service Pack 1;
  - Обновление **KB2999226** (Universal C Runtime / Visual C++ 2015-2022 Redistributable);
  - Обновление **KB3063858** (поддержка `SetDefaultDllDirectories` для безопасной загрузки DLL);
  - Обновление корневых сертификатов доверенных центров сертификации (включая ISRG Root X1 для валидации тайловых серверов OpenStreetMap/Mapbox).

### 3.2. Сетевой стек и TLS на Windows 7
В дистрибутив CPython 3.8.10 для Windows входит библиотека OpenSSL **1.1.1k**, которая штатно поддерживает протоколы **TLS 1.2** и **TLS 1.3** с современными алгоритмами шифрования (AES-GCM, ECDHE). При условии актуализации локального хранилища доверенных корневых сертификатов Windows 7 или поставки сертификатов `certifi`:
- Загрузка онлайн-тайлов OpenStreetMap по HTTPS проходит проверку подлинности сертификатов без отключения `verify`.
- Правило 7 этапа (запрет небезопасного TLS) полностью соблюдается.

### 3.3. Статус решения по Windows 7 (Decision Gate)
Статус: **BUILDABLE / NOT TARGET-TESTED**
- **Техническое обоснование**: Все необходимые бинарные зависимости существуют на PyPI, совместимы с Python 3.8 и компилируются под подсистему Windows NT 6.1 (Windows 7). Однако в текущем автоматизированном тестовом окружении отсутствует физическая машина или гипервизор с установленной ОС Windows 7 SP1. В строгом соответствии с правилами 41, 68 и 70, статус фиксируется как *сборка осуществима, но не проверена на целевой физической ОС*.

## 4. Детальный аудит Windows XP SP3: Ответы на 10 ключевых вопросов

### Вопрос 1: Какая последняя пригодная версия Python?
**Ответ: CPython 3.4.4** (релиз 21 декабря 2015 г., 32-bit x86).  
Начиная с Python 3.5.0, инсталлятор и бинарники CPython компилируются с использованием инструментария MSVC 2015 и Universal C Runtime (UCRT), требующего системных вызовов ядра NT 6.0+ (Vista) и блокирующего запуск на подсистеме NT 5.1 (Windows XP) с ошибкой *"Не является приложением Win32"*.

### Вопрос 2: Какой Qt binding реально запускается?
**Ответ: PyQt4 4.11.4 или PySide 1.2.4 (на базе Qt 4.8.7)**.  
Компания The Qt Company объявила Windows XP устаревшей в Qt 5.6 LTS (2016 г.), после чего поддержка была полностью удалена. Готовых колес PyQt5 для связки Python 3.4 + Win32 XP на официальном PyPI не существовало. Запуск современного PySide6 (Qt 6) физически невозможен.

### Вопрос 3: Какие numpy/pyproj/GDAL/rasterio доступны?
**Ответ**:
- `numpy`: последняя совместимая версия — **1.11.3 / 1.12.1** (сборка MSVC 2010 x86).
- `pyproj`: последняя версия — **1.9.5.1** (на базе устаревшего PROJ 4.9).
- `GDAL`: только устаревшие бинарные сборки **GDAL 1.11.x** (C API).
- `rasterio`: **НЕДОСТУПЕН**. Для rasterio требуется GDAL >= 2.0, Cython и компилятор C++14. Колес для Python 3.4 нет, сборка из исходников на XP невозможна.

### Вопрос 4: Есть ли рабочий современный CRS stack?
**Ответ: НЕТ**.  
Современная трансформация координат в GeoPoint Mapper базируется на PROJ 9+ и `proj.db` (база метаданных геодезических параметров в формате SQLite). На Windows XP доступен максимум PROJ 4.9, использующий устаревшие плоские proj-строки (`+proj=tmerc ...`), не поддерживающий современные методы интерполяции геодезических сеток (NTv2) и современные европейские/российские уточненные модели геоида.

### Вопрос 5: Есть ли безопасный HTTPS/TLS stack?
**Ответ: НЕТ (КРИТИЧЕСКИЙ БЛОКЕР)**.  
Системный криптопровайдер Windows XP (Schannel) не поддерживает протоколы TLS 1.2 и TLS 1.3 (максимум TLS 1.0, отключенный всеми современными веб-сервисами из-за уязвимостей POODLE/BEAST). CPython 3.4.4 скомпилирован со старой версией OpenSSL 1.0.1r, лишенной поддержки современных шифров. Корневые сертификаты Windows XP не обновлялись с 2014 года. Любое обращение к тайловым серверам OpenStreetMap или Mapbox завершается ошибкой рукопожатия TLS (`SSL routines:SSL3_GET_SERVER_CERTIFICATE:certificate verify failed`).  
Поскольку Правило 7 категорически запрещает `verify=False` и отключение сертификатов: **онлайн-карты на Windows XP полностью исключены**.

### Вопрос 6: Возможен ли GeoTIFF?
**Ответ: ЧАСТИЧНО (PARTIAL)**.  
Полнофункциональный бэкенд на базе `rasterio`/`GDAL` с перепроецированием на лету невозможен. Однако открытие несжатых и базовых LZW-сжатых TIFF-файлов без перепроецирования возможно через устаревший `Pillow 3.4.2` или прямой парсер тегов TIFF (`LegacyRasterBackend`).

### Вопрос 7: Возможен ли GeoPackage?
**Ответ: ЧАСТИЧНО (PARTIAL)**.  
Библиотека `pyogrio` недоступна. Однако спецификация OGC GeoPackage базируется на SQLite 3. Стандартная библиотека Python 3.4 включает модуль `sqlite3`, что позволяет напрямую считывать метаданные слоев из таблицы `gpkg_contents` и извлекать геометрии WKB.

### Вопрос 8: Возможны ли online maps?
**Ответ: НЕДОСТУПНЫ / ЗАБЛОКИРОВАНЫ (BLOCKED BY DEPENDENCY & TLS)**.  
Современные картографические тайловые серверы работают исключительно по HTTPS с обязательным требованием TLS 1.2+ и современных шифронаборов. Безопасное подключение невозможно.

### Вопрос 9: Возможен ли XLSX?
**Ответ: ДА (SUPPORTED)**.  
Библиотека `openpyxl 2.4.9` написана на чистом Python и полностью совместима с Python 3.4. Импорт и экспорт табличных данных Excel возможен.

### Вопрос 10: Возможна ли georeferencing subsystem?
**Ответ: ЧАСТИЧНО (PARTIAL)**.  
Математический расчет параметров аффинного 2D-преобразования (6 коэффициентов полинома первой степени по контрольным точкам МНК) представляет собой базовые алгебраические вычисления и может выполняться без внешних зависимостей. Однако графический рендеринг трансформированного изображения в холсте ограничен возможностями старого QPainter (Qt 4.8).

## 5. Решение по Windows XP (Decision Gate)

### Статус: XP = BLOCKED

### Техническое обоснование блокировки:
1. **Несовместимость синтаксиса Python**: Кодовая база GeoPoint Mapper разработана под современный Python (`requires-python = ">=3.12"`) и активно использует:
   - аннотации типов объединений через вертикальную черту `|` (PEP 604, Python 3.10+);
   - встроенные дженерики коллекций `list[...]`, `dict[...]`, `tuple[...]` (PEP 585, Python 3.9+);
   - f-строки `f"..."` (PEP 498, Python 3.6+);
   - декораторы `@dataclass` (PEP 557, Python 3.7+).  
   Попытка запуска текущих файлов на Python 3.4.4 вызывает немедленный `SyntaxError` на этапе синтаксического анализа первого же импортируемого модуля.
2. **Запрет на создание форка**: Правило 2 (*«One source tree»*) и Правило 71 (*«Не делать fork»*) прямо запрещают создание дублирующей кодовой базы `src/rme_mapper_xp/` или переписывание всего проекта на устаревший синтаксис.
3. **Отсутствие современного Qt**: PySide6 не существует под Windows XP. Портирование GUI на PyQt4 нарушило бы единство кодовой базы интерфейса.
4. **Невозможность безопасной сети**: Отсутствие поддержки современных криптографических стандартов TLS 1.2/1.3 и актуальных доверенных сертификатов блокирует сетевые возможности без снижения требований к безопасности.

**Вывод**: GeoPoint Mapper честно и открыто объявляет статус платформы **Windows XP: BLOCKED**. Проект не имитирует работоспособность на Windows XP и не компрометирует безопасность пользователей.
