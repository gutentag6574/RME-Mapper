# Аудит синтаксиса и языковых возможностей Python для Legacy-порта

В данном документе проанализированы синтаксические конструкции и стандартные модули, используемые в текущей кодовой базе GeoPoint Mapper, с точки зрения их совместимости с целевыми устаревшими версиями интерпретатора Python:
- **Python 3.8** (Windows 7);
- **Python 3.4** (Windows XP SP3 — последняя официальная версия CPython под Win XP).

---

> [!NOTE]
> **Важное архитектурное правило Этапа 11**:
> Текущий современный код (`requires-python = ">=3.12"`) **НЕ переписывается** под старый синтаксис прямо сейчас. Задача аудита — зафиксировать точные языковые границы, чтобы будущий порт (Этап по созданию Legacy-сборок) выполнялся по четкому шаблону без неожиданностей.

## 1. Сводный аудит синтаксических конструкций

| Конструкция / Возможность | Где используется в modern коде | Минимальная версия Python | Поведение в Python 3.8 (Win 7) | Поведение в Python 3.4 (Win XP) | Стратегия адаптации для Legacy XP |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Type Union через `|`** (`str | None`, `int | float`) | Практически во всех модулях `models/`, `coordinates/`, `services/` | Python 3.10+ (PEP 604) | **Синтаксическая ошибка** (без `from __future__ import annotations`) | **Синтаксическая ошибка** (`TypeError` при парсинге AST). Замена на `typing.Union[A, B]`, `typing.Optional[A]` либо исключение аннотаций в runtime. |
| **Встроенные дженерики** (`list[str]`, `dict[str, Any]`, `tuple[...]`) | Во всех аннотациях типов core | Python 3.9+ (PEP 585) | **Синтаксическая ошибка** в рантайме без future | **Синтаксическая ошибка**. Замена на `typing.List`, `typing.Dict`, `typing.Tuple` или удаление аннотаций. |
| **`dataclasses` (`@dataclass`)** | `models/map_point.py`, `models/point_style.py`, `models/map_profile.py`, `models/project_data.py` | Python 3.7+ (PEP 557) | **Поддерживается штатно** | **Отсутствует модуль `dataclasses`**. Замена на классические классы с явными `__init__`, `__repr__`, `__eq__` или использование бэкпорта `attrs`. |
| **f-strings (`f"..."`)** | По всему проекту (логирование, UI, форматирование) | Python 3.6+ (PEP 498) | **Поддерживается штатно** | **Синтаксическая ошибка** парсера. Замена на `.format(...)` или `%`. |
| **`match / case`** | Проверено: в текущем коде **не используется** | Python 3.10+ (PEP 634) | Не поддерживается | Не поддерживается | В кодовой базе используется классический `if / elif / else`. |
| **`pathlib.Path`** | `maps/`, `services/`, `ui/` | Python 3.4+ (PEP 428) | Поддерживается штатно | В Python 3.4 `pathlib` был экспериментальным модулем (без поддержки протокола `os.PathLike`, функции `open()` не принимали `Path`). Замена на `str(path)` и `os.path`. |
| **Позиционные параметры `/`** | Не используются в критических путях | Python 3.8+ (PEP 570) | Поддерживается | Не поддерживается | Не используются. |
| **Моржовый оператор `:=` (walrus)** | В ядре не используется | Python 3.8+ (PEP 572) | Поддерживается | Не поддерживается | Избегать использования в core. |

## 2. Аудит системных вызовов и Windows API

Проведен поиск прямых вызовов специфичных для операционной системы API:
- `ctypes.windll`, `win32api`, `win32con`, `winreg` — в кодовой базе `src/rme_mapper/` **прямые вызовы отсутствуют**.
- Оконные вызовы выполняются исключительно через Qt abstraction layer (`PySide6.QtWidgets`).
- Файловые операции выполняются через стандартные кроссплатформенные библиотеки Python (`os`, `pathlib`, `json`, `shutil`).
- В проекте **нет зависимостей от Windows 10-only API** на уровне бизнес-логики.
- Единственная точка интеграции с путями Windows — вспомогательный метод обнаружения системных директорий QGIS (`_setup_gis_environment` в `__init__.py`), который защищен проверками `candidate.is_dir() and candidate.exists()`, что предотвращает любые ошибки на других системах.

## 3. Оценка объема работ для будущего XP-порта

Для реализации будущего порта под Windows XP (Python 3.4 / PyQt4 / PySide 1.2) потребуется:
1. **Трансляция синтаксиса аннотаций типов и f-strings**:
   - Автоматическая трансформация скриптом-препроцессором (например, утилитами `future-fstrings` или `tokenize`/`ast-unparse`) либо легковесный форк core-файлов без modern-сахара.
2. **Замена `@dataclass` в моделях**:
   - Реализация компактного базового класса (или декоратора), предоставляющего автоматический `__init__`, `asdict` и `to_dict`.
3. **Реализация `LegacyGeoPackageBackend`**:
   - Чтение структуры таблиц SQLite3 без GeoPandas.
4. **Реализация геодезических вычислений WGS84**:
   - Чистая реализация прямой геодезической задачи (формулы Винсенти/Карни) без внешнего pyproj.
