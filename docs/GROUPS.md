# Организационные группы объектов (Этап 18)

## 1. Введение и концепция

В рамках Этапа 18 в картографической системе **GeoPoint Mapper** реализована легковесная система организационных групп объектов.

### Ключевые архитектурные принципы
1. **Одноуровневая структура (1:N)**: Каждая точка `MapPoint` может принадлежать максимум одной группе (`point.group_id: str | None`). Отсутствуют вложенные подгруппы и связи M:N для сохранения простоты и высокой производительности.
2. **Организационная, а не геометрическая сущность**: Группа не является геометрией GIS. Она служит исключительно для группировки, фильтрации, переключения видимости и навигации.
3. **Безопасность данных при удалении**: Удаление группы никогда не приводит к удалению входящих в нее точек. Точки безопасно переходят в виртуальную категорию «Без группы» (`Ungrouped`).
4. **Атомарный Undo/Redo**: Удаление группы, назначение группы множеству объектов, переименование, переключение видимости и импорт с созданием новых групп поддерживают полный откат в один шаг.
5. **Разовое применение стилей (Bulk Style)**: Группа не наследует стили динамически; массовое изменение стиля точки через контекстное меню группы разово обновляет параметры конкретных `MapPoint`.

## 2. Модели данных

### 2.1 Модель `ObjectGroup` (`rme_mapper.models.object_group`)

```python
@dataclass
class ObjectGroup:
    id: str = field(default_factory=lambda: str(uuid.uuid4()))
    name: str = ""
    description: str = ""
    visible: bool = True
```

- **`id`**: Уникальный идентификатор группы (UUID v4).
- **`name`**: Пользовательское название группы (1..100 символов). Имена уникальны в рамках проекта без учета регистра (`case-insensitive`).
- **`description`**: Описание назначения группы (до 1000 символов, опционально).
- **`visible`**: Флаг видимости группы (по умолчанию `True`).

### 2.2 Связь с `MapPoint`

В класс `MapPoint` добавлено поле:
```python
group_id: str | None = None
```
- Если `group_id is None`, точка считается принадлежащей виртуальной категории «Без группы» (`Ungrouped`).
- При удалении группы поле `group_id` у всех точек этой группы сбрасывается в `None`.

## 3. Формула эффективной видимости (Effective Visibility)

Отображение маркера, геодезической зоны и подписи точки на холсте карты и при экспорте определяется многоуровневой формулой конъюнкции:

$$\text{Visible}_{\text{effective}} = \text{GlobalVisibility} \land \text{GroupVisibility} \land \text{PointVisibility}$$

Где:
1. **`GlobalVisibility`**: глобальный тумблер в меню «Вид» (`show_points_visible` / `show_zones_visible`).
2. **`GroupVisibility`**:
   - Если `point.group_id is None`, видимость группы всегда считается `True`.
   - Если `point.group_id` задан, берется `group.visible`.
3. **`PointVisibility`**: индивидуальный флаг `point.visible` (управляемый чекбоксом в строке таблицы или в диалоге свойств).

При отключении видимости группы скрываются маркер точки, ее геодезическая зона и подпись.

## 4. Пользовательский интерфейс

### 4.1 Панель групп (`GroupsPanel`)
Располагается в левом сайдбаре между панелью слоев и таблицей точек:
- **Кнопка «+»**: создание новой группы через диалог `GroupDialog`.
- **Дерево групп (1 уровень)**:
  - **«Все объекты»**: виртуальный системный элемент, сбрасывающий групповую фильтрацию. Показывает суммарный счетчик объектов.
  - **«Без группы»**: виртуальный системный элемент, отображающий только точки с `group_id is None`.
  - **Пользовательские группы**: отображают чекбокс видимости, название и динамический счетчик точек в скобках `(N)`.
- **Горячие клавиши**:
  - `Insert`: создать новую группу.
  - `F2`: переименовать выбранную группу.
  - `Delete`: удалить выбранную группу (с подтверждением).

### 4.2 Контекстное меню группы
- «Переименовать группу...» (`F2`)
- «Изменить описание...»
- «Показать группу» / «Скрыть группу»
- Разделитель
- «Выбрать объекты группы» (выбирает **все реальные точки группы** в памяти и таблице, даже если часть из них временно скрыта активным поиском или фильтром категории — Правило A)
- «Приблизить к группе» (`Zoom to Group`)
- «Изменить стиль объектов группы...» (разовое массовое применение через стандартный `BulkPointStyleDialog`)
- Разделитель
- «Удалить группу» (`Delete`)

### 4.3 Презентационные фильтры в таблице точек (`PointsPanel`)
Таблица точек поддерживает одновременную комбинацию трех фильтров по условию `AND`:
$$\text{Filter} = \text{GroupFilter} \land \text{CategoryFilter} \land \text{SearchQuery}$$

- **Группа**: выбирается кликом по элементу в `GroupsPanel`.
- **Категория**: выпадающий список в шапке панели точек («Все категории» + уникальные категории проекта).
- **Поиск**: регистронезависимый мгновенный поиск по имени, номеру объекта, описанию и категории.
- **Индикатор количества**:
  - Если фильтр активен: `Показано X из Y` (RU) / `Showing X of Y` (EN).
  - Если фильтр не активен: `Всего точек: Y` (RU) / `Total Points: Y` (EN).

## 5. Групповые операции и транзакции Undo/Redo

1. **Удаление группы (`DeleteGroupCommand`)**:
   - Запрашивает подтверждение у пользователя.
   - Запоминает ID всех входящих точек.
   - Переводит точки в `Ungrouped` (`group_id = None`).
   - Удаляет группу из `GroupService`.
   - **Undo**: восстанавливает группу с ее оригинальным ID и возвращает всем точкам членство в этой группе.

2. **Перемещение точек в группу (`AssignPointsToGroupCommand`)**:
   - Поддерживает мультивыделение.
   - Запоминает индивидуальный предыдущий `group_id` каждой точки (позволяет безопасно перемещать точки из разных исходных групп).
   - **Undo**: восстанавливает исходную группу индивидуально для каждого объекта.

3. **Массовое изменение категории (`BulkChangeCategoryCommand`)**:
   - Позволяет изменить категорию для всех выделенных точек через диалог `ChangeCategoryDialog`.
   - **Undo**: восстанавливает индивидуальные предыдущие категории.

4. **Пакетный импорт (`ImportPointsCommand`)**:
   - Если файл содержит новые названия групп, они создаются автоматически (при включенной опции `create_missing_groups: bool = True`).
   - **Undo**: удаляет импортированные точки и удаляет созданные пустые группы в один шаг.

## 6. Сохранение проекта и обратная совместимость

- Формат проекта `.gpmap` содержит секцию `"groups"`:
  ```json
  "groups": [
    {
      "id": "uuid-1",
      "name": "Северный сектор",
      "description": "Объекты северного района",
      "visible": true
    }
  ]
  ```
- Каждая точка в массиве `"points"` сохраняет `group_id`:
  ```json
  {
    "id": "point-uuid",
    "name": "Скважина 1",
    "group_id": "uuid-1",
    ...
  }
  ```
- **Обратная совместимость и безопасность данных**:
  - Старые проекты без поля `"groups"` загружаются штатно; `groups` инициализируется пустым списком, а `group_id` точек — `None`.
  - Защита от повреждений (Orphan references): если `group_id` точки ссылается на несуществующую группу, он автоматически сбрасывается в `None` с записью предупреждения в журнал (`logger.warning`), проект не падает и точки не теряются.
  - Детерминированное разрешение дубликатов ID групп (Duplicate Group IDs): если в файле проекта обнаружено несколько групп с одинаковым идентификатором `id = X`, первая встреченная группа детерминированно сохраняет оригинальный `id = X`, а каждой последующей группе генерируется новый уникальный UUID. Точки, ссылающиеся на `group_id = X`, детерминированно остаются закрепленными за первой группой. Новый идентификатор второй группы не перехватывает чужие точки, предотвращая случайную потерю или искажение принадлежности объектов. Событие логируется как `logger.warning`.
