## 4. Главные архитектурные узкие места до оптимизации

1. **$O(N^2)$ при последовательном добавлении в `PointsPanel`**:
   Метод `add_row` по умолчанию вызывает `_update_category_combo_items()` и `_update_counter()`, которые в цикле опрашивают все строки от 0 до текущей. При загрузке 10 000 точек это вызывает 50 миллионов вызовов `item.data()`, а при 100 000 точек — 5 миллиардов, приводя к полному зависанию GUI.
2. **$O(N^2)$ при добавлении маркеров на холст без отложенного пересчета**:
   Метод `add_user_point` синхронно вызывает `_recalculate_labels_layout()`, пересчитывающий коллизии всех точек заново.
3. **Отсутствие вьюпорт-куллинга подписей**:
   При режиме подписей `all` на холсте рассчитываются экранные координаты, метрики шрифта и коллизии для всех 100 000 точек, даже если на экране видно только несколько десятков.
4. **$O(G \times N)$ в групповых счетчиках `GroupController`**:
   `refresh_groups_ui` сканирует весь список точек $G$ раз (по числу групп).
5. **Повторные вычисления геодезических зон**:
   Отсутствие LRU-кэша приводит к повторному расчету геометрии круга на эллипсоиде для точек с одинаковыми радиусами.
6. **Ограничение `MAX_PROJECT_FILE_SIZE = 50 MB`**:
   Блокирует открытие проектов со 100 000 точками (файл проекта занимает ~84 МБ).
