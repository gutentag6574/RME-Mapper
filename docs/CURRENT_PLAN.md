# GeoPoint Mapper — План проекта и правила разработки

**PRODUCT**: GeoPoint Mapper  
**CURRENT VERSION**: 0.12.0
**PYTHON PACKAGE**: `rme_mapper` (сохраняется без переименования)

## 1. Текущий статус: Завершенные этапы (1–22)

- **Этап 1–5**: Каркас приложения, универсальная архитектура слоев, рендеринг GeoPackage (вектор) и координатные преобразования WGS84 / произвольные СК.
- **Этап 6–9**: Пользовательские точки, геометрические формы (круг, квадрат, треугольник), RGB-палитра, геодезические зоны радиуса (м/км) и стек отмены/повтора (Undo/Redo).
- **Этап 10–12**: Чистый старт без карты, диалог инспекции слоев OpenMapDialog, мультивыделение, групповое редактирование, экранные подписи точек (Point Labels) и форматы проектов `*.gpmap` (с обратной совместимостью с `.rmeproject`).
- **Этап 13–14**: Полноценный пошаговый мастер импорта `ImportWizard` (файлы XLSX, CSV, TXT, автоопределение разделителей, кодировок, координат DD/DMS/XY, сопоставление колонок).
- **Этап 15**: Высококачественный растровый экспорт PNG/JPEG (`MapRenderer`, `ImageExportService`, координатная масштабная линейка, стрелка севера, адаптивная легенда).
- **Этап 16**: Поддержка растровых подложек GeoTIFF (`ModernGeoTiffBackend` на базе rasterio, многомасштабное динамическое окно, плавная навигация, инвариантность экранных значков).
- **Этап 17**: Расширенная модель объектов (номер объекта, описание, категория, история категорий, обводка маркера, прозрачность, стили границы зоны: solid/dash/dot), интерактивное перетаскивание маркера мыши (Move Point) с поддержкой Undo/Redo и Esc, расширенная видимость точек/зон и предотвращение наложения подписей на базе пространственной сетки (spatial grid).
- **Этап 18**: Группы и организация объектов (модель `ObjectGroup`, одноуровневая структура 1:N с точками, панель `GroupsPanel` с виртуальными узлами "Все объекты" и "Без группы", независимое управление видимостью групп, фильтрация точек по группе/категории/поиску со счетчиком `Показано X из Y`, безопасная политика удаления групп с переводом точек в "Без группы", массовое изменение категорий, сохранение в проектах с дедупликацией ID и автосбросом битых ссылок, импорт с колонкой группы и опцией автосоздания, атомарный Undo/Redo для всех операций с группами).
- **Этап 19**: Базовые ГИС-инструменты (геодезическое измерение расстояний ломаными линиями по эллипсоиду WGS84 с rubber-band превью, геодезическое измерение площади и периметра полигонов от 3 вершин, динамическая экранная масштабная линейка с шагами 1/2/5 м/км с автоскрытием при отсутствии карты, координатная сетка с адаптивным шагом 4–12 линий и лимитом безопасности <= 30 линий с поддержкой DD и спроецированных метров, интеграция опциональной сетки в экспорт PNG/JPEG, меню «Инструменты» и тулбар с горячими клавишами, взаимное исключение режимов без конфликтов с точками, панорамирование средней кнопкой мыши и колесом зума без сброса измерений, полная изоляция от состояния проекта и Undo/Redo, 88 новых тестов, 914/914 тестов пройдено).
- **Этап 20**: Онлайн-карты (базовые тайловые подложки: OpenStreetMap Standard, Mapbox Satellite, Mapbox Hybrid, Custom XYZ в проекции Web Mercator EPSG:3857, двухуровневое кэширование L1 QPixmap LRU / L2 Disk LRU с лимитом 500 МБ, сетевой загрузчик QNetworkAccessManager с соблюдением OSM Tile Usage Policy, User-Agent и лимитом параллелизма, изоляция API-ключей в AppSettingsService без записи в проект, экранный оверлей копирайта AttributionOverlayWidget, экспорт с водяным знаком копирайта, полная автономность и отказоустойчивость при офлайн-работе, 84 новых теста, 998/998 тестов пройдено).
- **Этап 21**: Ручная геопривязка растровых изображений по контрольным точкам (GCP), аффинное преобразование, оценка невязок, защита от half-pixel сдвига, валидация CRS и безопасная работа с изображениями.
- **Этап 22**: Экспорт точечных объектов и таблиц координат в CSV, TXT, XLSX и GeoJSON: области All/Selected/Visible, DD/DMS/X/Y, атомарная запись, валидация целевой CRS, сохранение ведущих нулей, локализация и настройки диалога. Добавлено 66 тестов; итоговый регрессионный набор — 1155 тестов.
- **Этап 23**: Оптимизация производительности для слабых ПК и больших проектов (1k, 10k, 50k, 100k точек). Пакетная загрузка проектов без O(N) циклов, лимит размера файла проекта увеличен до 128 МБ, пакетное наполнение и фильтрация таблицы точек PointsPanel, отсечение подписей по вьюпорту (Viewport Culling), кэширование QFontMetrics и экранный LOD на холсте, дебаунс на зуме и скролле, ограниченный LRU-кэш геодезических зон (2048), линейная сложность Undo/Redo без глубокого deepcopy, безопасный экспорт 100k и 4K рендеринг. Добавлено 76 тестов; итоговый регрессионный набор — 1231 тест (все пройдены, 0 RuntimeWarning).
- **Этап 24**: Адаптация и совместимость со старыми ОС (Windows 7 / Legacy, Windows XP Feasibility). Полная матрица совместимости 13 зависимостей (`docs/LEGACY_WINDOWS_FEASIBILITY.md`), централизованный сервис `RuntimeCapabilities`, сохранение метаданных неподдерживаемых карт при round-trip, деградация интерфейса при недоступности возможностей, профиль `requirements-win7.txt` (Python 3.8.10 + PySide2 5.15), детальный аудит Windows XP (статус `XP = BLOCKED`), статус Windows 7: `BUILDABLE / NOT TARGET-TESTED`. Внедрен слой `qt_compat` и `from __future__ import annotations` (100% совместимость AST с Python 3.8). Добавлено 18 тестов; итоговый регрессионный набор — 1258 тестов (все пройдены, 0 RuntimeWarning).

## 3. Обязательные правила разработки (Architecture & Code Hygiene)

1. **Никаких опережающих файлов (No Speculative Files)**:
   Запрещено создавать заглушки сервисов, моделей или утилит (`future_*`, `measurement_*`, `online_map_*`) до наступления соответствующего этапа.

2. **Никакого дублирования компонентов (No Duplicate Implementations)**:
   При необходимости нового диалога, контроллера или сервиса в первую очередь расширять существующие компоненты. Запрещено плодить суффиксы `Component2`, `NewComponent`, `ComponentV2`.

3. **Единый QAction на одно действие (No Duplicate QActions)**:
   Одно пользовательское действие обслуживается единственным экземпляром `QAction`, используемым одновременно в меню, панели инструментов и контекстных меню.

4. **Единый источник ГИС-логики (No Copy-Paste GIS Logic)**:
   - Проекции и трансформации СК: только [CoordinateService](file:///d:/RME-Mapper/src/rme_mapper/services/coordinate_service.py).
   - Геодезические расчеты и радиусы: только [GeodesicService](file:///d:/RME-Mapper/src/rme_mapper/services/geodesic_service.py).
   - Модель точки: только [MapPoint](file:///d:/RME-Mapper/src/rme_mapper/models/map_point.py) и [PointService](file:///d:/RME-Mapper/src/rme_mapper/services/point_service.py).
   - Группы объектов: только [ObjectGroup](file:///d:/RME-Mapper/src/rme_mapper/models/object_group.py) и [GroupService](file:///d:/RME-Mapper/src/rme_mapper/services/group_service.py).
   - Проекты: только [ProjectService](file:///d:/RME-Mapper/src/rme_mapper/services/project_service.py).
   - Импорт: только [ImportService](file:///d:/RME-Mapper/src/rme_mapper/importers/import_service.py).
   - Экспорт карты: только [MapRenderer](file:///d:/RME-Mapper/src/rme_mapper/exporters/map_renderer.py) и [ImageExportService](file:///d:/RME-Mapper/src/rme_mapper/exporters/image_export_service.py).
   - Экспорт объектов: только [ObjectExportService](file:///d:/RME-Mapper/src/rme_mapper/services/object_export_service.py).
   - Доступ к бэкендам: только [BackendFactory](file:///d:/RME-Mapper/src/rme_mapper/backends/factory.py).

5. **Правило чистого архива (Clean Archive Rule)**:
   В архивы исходного кода, релизы и передачи на код-ревью категорически запрещено включать:
   `.venv/`, `.git/`, `__pycache__/`, `*.pyc`, `.pytest_cache/`, `*.egg-info/`, `scratch/`, `build/`, `dist/`.
   Для экспорта чистого архива исходников использовать `git archive`.
