# Локализация и многоязычность GeoPoint Mapper (Этап 12)

В документе описана архитектура локализации, система перевода интерфейса, правила добавления новых языков, механизм хранения настроек и гарантии независимости пользовательских данных в приложении **GeoPoint Mapper**.

---

## 1. Архитектура локализации

Локализация в GeoPoint Mapper построена на чистом Python без зависимости от скомпилированных бинарных файлов `*.qm` / `*.ts`, что обеспечивает:
- 100% переносимость между версиями Python (Python 3.12+, Python 3.8, Python 3.4);
- легкость аудита и редактирования словарей переводов;
- независимость от наличия бинарных утилит Qt (`lupdate`, `lrelease`);
- быстродействие и отсутствие внешних рантайм-зависимостей.

### Структура пакета `rme_mapper.i18n`

```text
src/rme_mapper/i18n/
├── __init__.py               # Публичный API: tr, get_language, set_language, get_translation_service
├── translation_service.py    # Сервис управления переводами, сигналами и fallback-логикой
├── translations_ru.py        # Словарь русских строк (эталонный словарь)
└── translations_en.py        # Словарь английских строк (100% симметричный набор ключей)
```

|---|---|---|---|
| `ru` | Русский | Полная поддержка | **Да** (первичный язык) |
| `en` | English | Полная поддержка | Нет |

## 3. Публичный API локализации

Основная функция доступа к локализованным строкам:

```python
from rme_mapper.i18n import tr, get_language, set_language

# Простой перевод
label = tr("menu.file")

# Перевод с параметрической подстановкой
status = tr("status.map_info", name="Марий Эл", crs="EPSG:4326", count=5)

# Проверка и установка активного языка
current = get_language()  # "ru"
set_language("en")        # переключение на English
```

### Принцип безопасного fallback
1. Если запрошенный ключ отсутствует в активном языке (например, `en`), сервис пытается извлечь его из эталонного языка (`ru`).
2. Если ключ отсутствует во всех словарях, возвращается сам строковый ключ (например, `"unknown.key"`), без возбуждения исключений и сбоев интерфейса.

## 4. Соглашение об именовании ключей (Naming Convention)

Все ключи строятся по иерархическому принципу с точечной нотацией:
`<модуль_или_контекст>.<подкатегория>.<идентификатор>`

Примеры:
- `menu.file`, `menu.map`, `menu.settings`, `menu.language` — заголовки меню верхнего уровня;
- `action.new_project`, `action.open_map`, `action.exit` — действия и пункты меню;
- `panel.layers`, `panel.points`, `panel.properties` — заголовки панелей;
- `table.col_index`, `table.col_name`, `table.col_lat` — заголовки таблицы точек;
- `dialog.point.title_add`, `dialog.point.btn_save` — элементы диалога точек;
- `dialog.map.source_group`, `dialog.map.btn_open` — элементы диалога открытия карты;
- `dialog.about.title`, `dialog.about.author` — элементы диалога «О программе»;
- `val.coord.lat_range`, `val.dms.lat_deg_range` — сообщения ошибок валидации координат;
- `val.style.symbol_unknown`, `val.zone.radius_range` — сообщения ошибок валидации стиля и зоны;
- `shape.circle`, `shape.square`, `shape.triangle` — локализованные отображаемые имена фигур;
- `unit.km`, `unit.m` — локализованные единицы измерения расстояния.

## 5. Динамическое переключение «на лету» (Live Switching)

Переключение языка происходит **мгновенно без перезапуска приложения**:
1. Пользователь выбирает язык в меню: `Настройки -> Язык -> Русский / English`.
2. Вызывается `MainWindow.switch_language(lang_code)`.
3. `TranslationService.set_language(lang_code)` активирует новый словарь и испускает сигнал Qt `language_changed`.
4. Метод `retranslate_ui()` вызывается на всех компонентах:
   - `MainWindow.retranslate_ui()`: меню, действия, панели, заголовки таблицы точек, панель свойств, строка состояния, заголовок окна;
   - `MapCanvas.retranslate_ui()`: оверлей пустого старта, кнопка «Показать всю карту»;
   - `PointDialog.retranslate_ui()`, `OpenMapDialog.retranslate_ui()`, `AboutDialog.retranslate_ui()`.

### Гарантии сохранения состояния:
- **Загруженная карта**: не выгружается и не перезагружается;
- **Слои**: видимость и порядок слоев не сбрасываются;
- **Пользовательские точки**: координаты, цвета, радиусы зон и имена точек остаются неизменными;
- **Таблица**: строки не пересоздаются; обновляются только локализованные колонки («Форма» и единицы «Радиуса»);
- **Флаг изменений (`is_modified`)**: переключение языка **не считает** проект измененным;
- **Текущий путь проекта**: сохраняется в точности.

## 6. Хранение настроек (AppSettingsService)

Язык интерфейса сохраняется в пользовательском окружении через сервис `AppSettingsService`:
- Используется обертка над `PySide6.QtCore.QSettings` (организация `GeoPointMapper`, приложение `GeoPointMapper`, ключ `ui/language`);
- При отсутствии Qt или при запуске консольных тестов работает встроенный memory-fallback;
- Настройка языка сохраняется сразу в момент выбора пользователем;
- При следующем запуске приложения язык восстанавливается из настроек.

> [!IMPORTANT]
> **Формат проекта `*.gpmap` НЕ хранит язык приложения.**
> Язык интерфейса — это глобальное предпочтение пользователя компьютера, а файл проекта — документ с географическими данными, независимый от локали.

## 7. Независимость пользовательских и картографических данных

Система строго разделяет локализуемый UI-текст и данные моделей:

| Сущность | Поведение при смене языка |
|---|---|
| Имена точек, введенные пользователем | **Не переводятся** (сохраняются как ввел пользователь) |
| Авто-имя новой точки | Генерируется на активном языке («Точка N» в RU, «Point N» в EN), но после создания не меняется |
| Внутренний код формы маркера (`symbol`) | Всегда `'circle'`, `'square'`, `'triangle'` (независимо от UI) |
| Единицы радиуса зоны в модели (`radius_m`) | Всегда число в метрах `float` (в UI отображается как `км` / `km` или `м` / `m`) |
| Идентификаторы слоев GeoPackage (`id`, `source_name`) | **Не переводятся** (сохраняют оригинальные имена слоев из файла карты) |
| Имена и CRS профилей карт (`MapProfile`) | **Не переводятся** |
| Сведения об авторе («Кульдеев Вадим Алексеевич», контакты) | **Не переводятся** |

## 8. Локализация ошибок валидации

Ошибки валидации координат, стилей и зон генерируют исключение `ValidationError`:

```python
from rme_mapper.coordinates.validator import ValidationError

class ValidationError(ValueError):
    """Исключение валидации с кодом ошибки и параметрами."""
    def __init__(self, code: str, **params: Any): ...
    def localized_message(self, lang: str | None = None) -> str: ...
    def __str__(self) -> str: ...
```

- `ValidationError` наследуется от стандартного `ValueError`, что гарантирует 100% обратную совместимость с кодом и тестами предыдущих этапов;
- `str(err)` автоматически форматирует сообщение на текущем активном языке приложения;
- `err.code` позволяет программно идентифицировать ошибку независимо от языка интерфейса.

## 9. Правила добавления новых ключей и языков

При добавлении новых UI-компонентов:
1. Добавить ключ в `src/rme_mapper/i18n/translations_ru.py`.
2. Добавить **тот же самый ключ** в `src/rme_mapper/i18n/translations_en.py`.
3. Убедиться, что количество ключей и их состав строго симметричны:
   ```bash
   pytest tests/test_stage12.py -k "test_10_translations_symmetry_and_counts"
   ```
4. В UI-коде обращаться к строке через `tr("key.name", param=val)`.
5. Добавить вызов обновления в метод `retranslate_ui()` соответствующего окна или диалога.
