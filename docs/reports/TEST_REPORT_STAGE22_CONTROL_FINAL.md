## 6. Исправление поведения при невалидной Target CRS (Invalid CRS Corrected Behavior)
* **Устраненный блокер:** Ранее при ошибке проецирования поля X/Y оставались пустыми при успешном завершении экспорта.
* **Новая логика:**
  - Если пользователь включил экспорт спроецированных координат (`x`, `y` или `crs`) и целевая CRS не задана, невалидна, не может быть создана или трансформация невозможна:
    1. **В GUI (`ExportObjectsDialog`):** при нажатии кнопки экспорта метод `_on_export_clicked` выполняет предварительную валидацию через `pyproj.CRS.from_user_input` и проверку инициализации `pyproj.Transformer`. При ошибке пользователю выводится модальное предупреждение (`QMessageBox.warning`), диалог не закрывается, целевой файл не создается.
    2. **В сервисном слое (`ObjectExportService.export_points`):** валидация Target CRS выполняется ДО создания временного файла и ДО записи на диск. При невалидной CRS выбрасывается `ValueError` с локализованным описанием.
    3. **В генераторе записей (`build_export_record`):** при сбое математического пересчета координат точки (`CoordinateService.transform_xy`) при запрошенных полях X/Y выбрасывается `ValueError`, прерывающий экспорт.
    4. **Атомарная защита:** При возникновении ошибки временный `.tmp` файл гарантированно удаляется (`unlink`), исходный целевой файл остается нетронутым, флаг `project.is_modified` и история Undo не изменяются. Создание успешного файла с пустыми X/Y полностью исключено.
