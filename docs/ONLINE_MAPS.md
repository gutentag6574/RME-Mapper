# Онлайн-карты: Standard / Satellite / Hybrid (Online Basemaps) — GeoPoint Mapper

Документация по поддержке онлайн-тайловых картографических подложек (XYZ Tiles) в рамках **Этапа 20**.

---

## 1. Обзор возможностей

В рамках Этапа 20 в **GeoPoint Mapper** добавлена поддержка онлайн-тайловых подложек в качестве нового типа базовой карты (`source_type="online_xyz"`).

### 1.1. Поддерживаемые типы карт
1. **Стандартная карта (Standard / OSM)**:
   - Провайдер: **OpenStreetMap Standard** (`osm_standard`).
   - Доступна бесплатно, не требует API-ключа.
   - Полноценная картографическая схема улиц, зданий и гидрографии.
2. **Спутниковая карта (Satellite / Mapbox)**:
   - Провайдер: **Mapbox Satellite** (`mapbox_satellite`).
   - Детализированные аэрофото- и космические снимки сверхвысокого разрешения.
   - Требует бесплатный Mapbox Access Token.
3. **Гибридная карта (Hybrid / Mapbox)**:
   - Провайдер: **Mapbox Satellite Streets** (`mapbox_hybrid`).
   - Спутниковый снимок с наложением дорожной сети, границ и топонимов.
   - Требует Mapbox Access Token.
4. **Пользовательский XYZ-сервер (Custom XYZ)**:
   - Произвольный шаблон URL вида `https://tile.example.com/{z}/{x}/{y}.png`.
   - Настраиваемый диапазон зумов (0..22).
   - Опциональный API-ключ в query-параметре или заголовке.

## 2. Архитектура и математика тайлов

### 2.1. Проекция Web Mercator (`EPSG:3857`)
Все онлайн-тайлы стандартно используют проекцию Spherical Mercator (Web Mercator, EPSG:3857):
- Координаты сцены хранятся и отображаются в метрах Web Mercator.
- Пересчет между широтой/долготой (WGS84, `EPSG:4326`) и метрами Web Mercator выполняется в сервисе `src/rme_mapper/services/tile_math.py`:
  - `TileMath.lonlat_to_mercator(lon, lat) -> tuple[float, float]`
  - `TileMath.mercator_to_lonlat(x, y) -> tuple[float, float]`
- Вычисление номера тайла по координатам и зуму:
  - $x = \lfloor \frac{\text{lon} + 180}{360} \cdot 2^z \rfloor$
  - $y = \lfloor (1 - \frac{\ln(\tan(\text{lat}\cdot\pi/180) + 1/\cos(\text{lat}\cdot\pi/180))}{\pi}) \cdot 2^{z-1} \rfloor$
- Вычисление оптимального масштаба (zoom level) по текущему разрешению экрана `units_per_pixel`:
  - $\text{zoom} = \text{round}(\log_2(\frac{C}{256 \cdot \text{res}}))$, где $C \approx 40075016.68557849\text{ м}$.

## 3. Сетевой загрузчик и соответствие Tile Usage Policy

Сетевой загрузчик `TileLoader` (`src/rme_mapper/services/tile_loader.py`) строго соблюдает **OpenStreetMap Tile Usage Policy**:

1. **Идентификация User-Agent**:
   - Каждый исходящий HTTP-запрос передает обязательный заголовок:
     `User-Agent: GeoPoint Mapper/0.11.0 (+https://github.com/gutentag6574/RME-Mapper)`
2. **Ограничение параллельных соединений (Rate Limiting)**:
   - Для серверов OpenStreetMap действует строгое ограничение: **не более 2 одновременных сетевых запросов**.
   - Для коммерческих провайдеров (Mapbox и др.) ограничение составляет 4 соединения.
3. **Дедупликация запросов**:
   - Если тайл уже находится в очереди загрузки, повторный запрос объединяется с текущим, исключая дублирующий сетевой трафик.
4. **Отмена устаревших запросов (Stale Cancellation)**:
   - При быстром панорамировании или изменении масштаба (зума) тайлы, вышедшие за пределы области видимости, автоматически удаляются из очереди ожидания.
5. **Сетевой стек**:
   - Используется стандартный асинхронный `PySide6.QtNetwork.QNetworkAccessManager` (без внешних зависимостей `requests` / `urllib3`).

## 4. Двухуровневое кэширование

1. **Кэш в оперативной памяти (L1 Memory Cache)**:
   - Реализован в `OnlineTileManager` через `OrderedDict[tuple[int, int, int], QPixmap]`.
   - Емкость по умолчанию: **256 тайлов**.
   - Стратегия вытеснения: строгий **LRU (Least Recently Used)**.
   - Моментальная отрисовка без дискового ввода-вывода.
2. **Кэш на жестком диске (L2 Disk Cache)**:
   - Реализован в `TileDiskCache` (`src/rme_mapper/services/tile_cache.py`).
   - Каталог хранения: `%LOCALAPPDATA%/GeoPointMapper/tile_cache/<provider_id>/<z>/<x>/<y>.png`.
   - Емкость по умолчанию: **500 МБ** (настраивается в параметрах).
   - Защита от повреждений: валидация сигнатур файлов (Magic Bytes: PNG, JPEG, WebP).
   - Защита безопасности: строгая проверка на Path Traversal атаки.
   - Механизм очистки: вытеснение по LRU при превышении лимита размера, ручная очистка пользователем через меню.

## 5. Безопасность API-ключей

В соответствии с принципами безопасности GeoPoint Mapper:
- **API-ключи и приватные токены никогда не сохраняются в файле проекта (`*.gpmap`)**.
- Файл проекта сохраняет только метаданные провайдера: `provider_id`, `map_type`, `crs="EPSG:3857"`, `source_type="online_xyz"`.
- Все ключи сохраняются исключительно в защищенном локальном профиле пользователя через `AppSettingsService`.
- При открытии проекта на другом компьютере или без сохраненного ключа приложение запрашивает ввод токена через диалоговое окно `OnlineBasemapDialog`.

---

## 6. Автономная работа и отказоустойчивость (Offline Resilience)

При отсутствии подключения к сети Интернет или блокировке серверов:
1. Все ранее загруженные тайлы мгновенно читаются из дискового кэша.
2. Для отсутствующих тайлов отображается нейтральная заглушка (placeholder) с координатной сеткой тайла.
3. Приложение не падает, не блокирует GUI и не показывает навязчивых модальных окон об ошибках сети.
4. **Все функции ГИС работают на 100%**:
   - Нанесение, перемещение и редактирование точек и групп;
   - Измерение расстояний и площадей;
   - Отображение масштабной линейки и координатной сетки.

## 7. Экспорт и копирайт (Attribution Watermark)

1. **Экранный водяной знак (Attribution Overlay)**:
   - Виджет `AttributionOverlayWidget` закреплен в правом нижнем углу карты.
   - Отображает обязательный копирайт провайдера:
     - Для OpenStreetMap: `© OpenStreetMap contributors`
     - Для Mapbox: `© Mapbox © OpenStreetMap`
   - Полупрозрачная контрастная подложка с кликабельной гиперссылкой.
2. **Экспорт в растровые форматы (PNG / JPEG)**:
   - Рендерер `MapRenderer` запекает тайлы онлайн-подложки в высоком разрешении.
   - В диалоге экспорта доступна опция «Включать копирайт подложки» (по умолчанию включена).
   - Декоратор `MapDecorationRenderer.render_attribution` размещает аккуратный водяной знак в углу итогового изображения.
