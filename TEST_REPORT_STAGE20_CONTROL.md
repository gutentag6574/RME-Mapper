## 3. Статус Cache TTL и HTTP Caching

- **Дефолтный TTL:** **7 дней** (`DEFAULT_CACHE_TTL_DAYS = 7`), что строго удовлетворяет требованиям OSM Tile Usage Policy (кэш не менее недели при отсутствии директив сервера).
- **Файлы метаданных (.meta):** Рядом с каждым файлом тайла `*.tile` сохраняется сайдкар `*.meta` в формате JSON:
  - `etag` — HTTP ETag сервера.
  - `last_modified` — дата последнего изменения HTTP.
  - `stored_at` — UNIX timestamp момента сохранения.
  - `max_age` / `cache_control` / `expires` — заголовки контроля кэша.
- **Условные HTTP-запросы (Conditional Requests):**
  - При истечении срока жизни тайла (TTL) `OnlineTileManager` немедленно отображает существующий тайл из кэша, предотвращая мерцание, и ставит в фоновую очередь условный запрос с заголовками `If-None-Match: <etag>` и `If-Modified-Since: <last_modified>`.
  - При получении `HTTP 304 Not Modified` тело тайла повторно по сети не передается (0 байт сетевого трафика на пиксели), обновляется поле `stored_at` в `.meta`, и тайл продлевается на следующий период TTL.
- **Защита от Bulk/Prefetch:** В коде `OnlineTileManager` и `TileMath` отсутствует упреждающая предзагрузка (prefetch) или пакетное скачивание (bulk download). Загружаются строго тайлы, входящие в текущий `bounding box` видимой области `MapCanvas` на текущем зуме.

## 4. Статус соответствия Mapbox (Токены, Логотип, Спецификация)

- **URL-шаблоны:**
  - Satellite: `https://api.mapbox.com/v4/mapbox.satellite/{z}/{x}/{y}@2x.png?access_token={api_key}`
  - Hybrid: `https://api.mapbox.com/styles/v1/mapbox/satellite-streets-v12/tiles/256/{z}/{x}/{y}@2x?access_token={api_key}`
- **Рендеринг логотипа Mapbox (`logo_required = True`):**
  - Реализован рендерер декораций `MapDecorationRenderer.render_attribution()`, поддерживающий параметр `logo_required`.
  - В левой части бейджа атрибуции отрисовывается фирменный бейдж `mapbox | © Mapbox © OpenStreetMap`.
- **Блокировка Secret Tokens (`sk...`):**
  - Любая попытка ввода секретного токена (`sk.ey...`) немедленно блокируется валидатором `OnlineBasemapDialog` с выводом критической ошибки: *«Обнаружен секретный токен Mapbox (sk...). Секретные токены запрещены для безопасности. Используйте только публичный токен (pk...)»*.
  - В модели `OnlineProviderConfig.get_effective_api_key()` и `build_tile_url()` выбросится исключение `ValueError`, если будет передан токен, начинающийся на `sk.`.
  - В `AppSettingsService.set_provider_api_key()` секретный токен `sk...` отсекается и не сохраняется в `QSettings`.
- **Публичные токены (`pk...`):**
  - Разрешены, принимаются и сохраняются в локальных пользовательских настройках `QSettings`.
  - Хранилище `QSettings` в документации и коде явно задокументировано как конфигурация рабочего стола (не защищённое системное хранилище секретов).
- **Маскирование токенов в логах:**
  - Функция `sanitize_url(url)` автоматически заменяет все токены (`pk.*`, `sk.*`, параметры `access_token=`, `api_key=`, `key=`) на безопасное значение `[REDACTED]`. Ни в один лог-файл или трейсбэк исходный токен не попадает.

## 6. Статус валидации содержимого и повреждённого кэша

- **Повреждённые тайлы 0 байт:** Валидатор `TileDiskCache.is_valid_image(data)` определяет файл как невалидный. Невалидный файл удаляется из кэша, запрашивается свежая версия с сервера.
- **Отклонение HTML-ответов:** Если сервер провайдера или captive-portal возвращает HTTP 200 с `Content-Type: text/html` либо в первых 512 байтах обнаруживаются теги `<!doctype html`, `<html`, `<?xml`, `<svg`, такой ответ **строго отклоняется**, сигнал успешной загрузки не эмитируется, файл в дисковый кэш не сохраняется.
- **Проверка Magic Bytes:** При валидации проверяются сигнатуры форматов:
  - PNG: `89 50 4E 47 0D 0A 1A 0A`
  - JPEG: `FF D8 FF`
  - WebP: `52 49 46 46 ... 57 45 42 50`
  Любые другие бинарные данные отсекаются.
